# Config

WP Canon keeps configurable behavior inside `config/`.

The goal is to avoid hardcoded project-specific logic.

---

# Current Config Files

## `config/content-types.json`

Generated by:

```bash
npm run discover
```

Contains:
- discovered REST post types
- post type metadata
- local folder mappings

---

# Planned Config Files

## `config/semantic.json`

Potential future config for:
- semantic rules
- clustering thresholds
- broad keyword tuning
- scoring weights

---

## `config/language-packs/`

Potential future language-specific config.

Examples:

```text
config/language-packs/en.json
config/language-packs/nl.json
```

Could contain:
- stopwords
- generic anchors
- fallback anchor filler and intent words
- weak phrase patterns
- language heuristics

---

# Config Philosophy

Prefer:
- configurable heuristics
- inspectable rules
- deterministic behavior

Avoid:
- hidden magic
- project-specific hardcoding
- deeply embedded constants

---

# Important Rule

Client-specific or niche-specific logic should never live in core heuristics.

If customization is needed:
- make it configurable
- isolate it
- document it
